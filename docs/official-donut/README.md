# Official Donut â€” integration contract for CareerFlow

Status: authoritative reference for how CareerFlow talks to the **official
installed Donut Browser** (verified against v0.31.3 on 2026-10-03). This
document replaces the retired DBI-era integration notes; nothing in this file
describes a modified, bundled, or patched Donut.

## The one rule

Donut is an independently installed, user-owned application. CareerFlow
**connects** to it and never owns it. Concretely, CareerFlow must NEVER:

- launch, spawn, or auto-start Donut
- stop, kill, terminate, or shut down Donut (or call any shutdown endpoint)
- modify, patch, fork, rebuild, or bundle Donut or its Wayfern engine
- modify Donut's settings or its account/licensing state
- read, print, log, or store the API token outside request-header scope
- assume a DBI workspace, `runtime.json`, a pinned backend, or `/health`

The user starts and stops Donut themselves (and its lifetime outlives
CareerFlow; quitting CareerFlow must not touch it).

## CareerFlow R6 integration boundary — 2026-10-11

This section supersedes the historical **Playwright-over-CDP** implementation description later in this document. The Playwright/CDP material records an old implementation and security research, not an allowed production integration contract.

CareerFlow production integration uses the official authenticated Donut Local REST API for user-initiated profile opening and URL opening, plus local CareerFlow-owned profile/shortcut metadata. The main-process Browser Manager continues to own the supported paths (`POST /v1/profiles/{id}/run` for explicit profile open/reuse and `POST /v1/profiles/{id}/open-url` for a stored HTTP(S) shortcut), with existing ownership checks, bearer token handling, and truthful failure/fallback behavior. The [current official REST API reference](https://donutbrowser.com/docs/rest-api/) identifies both endpoints as Pro-gated; CareerFlow surfaces upstream refusal/failure honestly rather than bypassing the tier check. Profile/shortcut CRUD stays in Browser Manager and the local CareerFlow database.

CareerFlow no longer registers the `cdp:*` IPC surface. Its `browser-workspace:*` compatibility channels and legacy `browser_*` agent tools return `feature-not-supported` and do not create CDP sessions, inspect tabs/pages, take browser screenshots, click/type, or manipulate Donut HWND/PID foreground state. Those operations are not claimed to be supported by the Local API. The normal CareerFlow-owned Electron `WebContentsView` remains independent of Donut and is the supported place for in-app browsing.

The legacy adapter/session and old workspace operation source files remain in the repository as dormant historical/test fixtures for now. They are not reachable through the registered production IPC graph. They were not removed here because the protected CDP checker has positive legacy transport/authentication assertions; changing its rules was expressly out of scope. The raw same-user DevTools WebSocket authentication issue remains **BLOCKED** in `docs/CDP-AUTH-BOUNDARY.md`, even though CareerFlow production no longer uses that transport to control Donut.

## Authentication model

- Every Local API request needs `Authorization: Bearer <token>`; unauthenticated
  requests get `401`. The token is generated by the app and the user can copy
  it from Settings â†’ Integrations â†’ Local API.
- Stored encrypted: `api_token.dat` is `DBAPI` v2 = header `"DBAPI"` | version
  byte `0x02` | salt (b64) | 12-byte nonce | AES-256-GCM ciphertext (tag
  appended). Key = Argon2id over the raw `vault.key` bytes (m=19456, t=2, p=1,
  32-byte output). Reference implementation: `shell/src/services/donut-credential.js`.
- **Never store or expose the token.** It lives in fetch headers only; status
  payloads, logs, and renderer surfaces must never contain it.

## Official REST surface (`http://127.0.0.1:<api_port>`)

Machine-readable contract: **`GET /openapi.json`** (48 paths as of 0.31.3;
note `/v1/openapi` is 404 â€” the spec is at the root path). Endpoints CareerFlow
depends on:

| Endpoint | Use in CareerFlow |
|---|---|
| `GET /v1/profiles` | liveness/connect probe + profile listing |
| `GET /v1/profiles/{id}` | profile read; reports `is_running`, `remote_debugging_port`, `process_id` |
| `POST /v1/profiles` | profile create (`browser: "wayfern"`); mapping/`cf-` names |
| `POST /v1/profiles/{id}/run` | **launch; response requires `remote_debugging_port`** (Pro-gated) |
| `POST /v1/profiles/{id}/kill` | stop one browser (user-initiated Stop button) |
| `POST /v1/profiles/{id}/open-url` | open a URL in a new tab of a running profile |
| `DELETE /v1/profiles/{id}` | profile deletion (test cleanup only) |

There is **no `/health` endpoint** (it 401s unauthenticated and 404s with a
bearer; it is absent from the OpenAPI spec) and **no `/tabs` endpoints**. Tab
control is Playwright/CDP only. The spec also documents a `/v1/profiles/{id}/agent/*`
family (click/type/perceive/extract/pick/resolve-locator) not yet used here.

## Playwright-over-CDP (the browser-control contract)

Officially documented flow (Quickstart / Wayfern docs):

```
POST /v1/profiles/{id}/run  â†’  { profile_id, remote_debugging_port, headless }
chromium.connectOverCDP(`http://127.0.0.1:<remote_debugging_port>`)
â†’ normal Playwright BrowserContext/Page APIs
```

CareerFlow maps browser operations to Playwright:

| Operation | Playwright API |
|---|---|
| Back | `page.goBack()` |
| Forward | `page.goForward()` |
| Reload | `page.reload()` |
| List tabs | `browserContext.pages()` |
| Create tab | `context.newPage()` (or REST `open-url`) |
| Close tab | `page.close()` |
| Activate tab | `page.bringToFront()` |

Implementation: `shell/src/services/cdp-session.js` (connection + page
mapping) and `shell/src/services/cdp-adapter.js` (ownership gate + REST
fallbacks), both behind the `BrowserProvider` seam
(`shell/src/services/browser-provider/`). Security gate:
`scripts/check-cdp-auth-boundary.mjs` â€” zero raw WebSocket, zero `/json/*`
discovery, zero DevTools URL construction in production code; Playwright is
imported only in `cdp-session.js`; the renderer never sees endpoints, ports,
or the token.

**Known upstream gap (documented, BLOCKED):** the browser's raw DevTools
WebSocket listener is unauthenticated at the transport level. CareerFlow's
transport never uses it, but the gap is a property of the browser runtime
(`docs/CDP-AUTH-BOUNDARY.md`, evidence probe
`e2e/devtools-auth-boundary-evidence.spec.js`).

## Pro limitation (as of 0.31.3)

`POST /v1/profiles/{id}/run` is **Pro-gated**: on a non-Pro account it answers
`402` (documented response in the OpenAPI spec). Effects:

- CDP/browser-runtime validation cannot run live without Pro; hermetic
  Playwright tests (`shell/tests/cdp-session.test.js` etc.) cover the path.
- Profile management, open-url fallbacks, and connect/probe all work without
  Pro (verified live). CareerFlow must handle 402 gracefully (typed failure,
  system-browser fallback) and never attempt to bypass or purchase licensing.

## Compatibility notes (0.31.2 â†’ 0.31.3)

- Contract unchanged between the two versions; `RunProfileResponse` marks
  `profile_id`, `remote_debugging_port`, `headless` as **required** fields.
- Local MCP is **removed** upstream (the old `127.0.0.1:51080` endpoint
  answers a `410` tombstone); remote MCP is a separate cloud surface and is
  out of scope for CareerFlow. Never build on local MCP.
- Wayfern engine (e.g. 152.x) is auto-downloaded by the app; its version is
  not part of the API contract.
- `killBrowser` in CareerFlow's adapter maps to REST `/v1/profiles/{id}/kill`
  (browser-scoped) â€” it never terminates the Donut application process.
